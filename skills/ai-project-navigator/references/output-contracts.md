# قالب پاسخ کوتاه

## وقتی اطلاعات کافی است

**برداشت من:** یک یا دو جمله دربارهٔ هدف، مرحله و محدودیت اصلی؛ فرض مؤثر را روشن کن.

**مسیر پیشنهادی:** ۳ تا ۵ مرحلهٔ کوتاه با ترتیب روشن؛ مرحلهٔ فعلی را نام ببر. یک جمله دلیل انتخاب و در صورت نیاز شرط رفتن به گزینهٔ پیچیده‌تر.

**چک‌لیست الان:** ۵ تا ۸ بند مرتب، به این شکل:
- [ ] یک تصمیم مشخص متناسب با پروژه — تکمیل وقتی: یک نشانهٔ کوتاه و قابل‌تشخیص.

**فعلاً لازم نیست:** حداکثر ۲ تا ۳ مورد با دلیل متناسب؛ اگر حذف موردی کمک نمی‌کند این قسمت را نیاور.

**تصمیم‌های باز:** فقط فرض یا ابهامی که هنوز اثر دارد؛ اگر ندارد حذف کن.

**ارتباط با دوره:** ۲ تا ۴ مورد کوتاه و قابل‌فهم. قالب هر مورد:
- جلسهٔ N، نام بخش — موضوعی که در این پاسخ استفاده شد.

شناسه‌های C و A را در خروجی عادی نشان نده. آن‌ها فقط برای ردیابی داخلی هستند. اگر کاربر ردیابی دقیق خواست، شمارهٔ چک‌لیست و شناسه را بعد از توضیح انسانی اضافه کن. موضوعی را که در پاسخ استفاده نشده است، فقط برای کامل‌کردن فهرست منابع نیاور. برای راهنمای نام جلسه‌ها و ارتباط موضوع‌ها، `course-topic-map.md` را بخوان.

اگر پاسخ از یک قاعدهٔ افزوده استفاده کرد که منبع مستقیم در دوره ندارد، یک مورد کوتاه با عنوان «تکمیل اسکیل» اضافه کن و کاربرد آن را بگو؛ برای نمونه «تکمیل اسکیل — محدودکردن دامنهٔ نسخهٔ اول با توجه به زمان و بودجه».

این عنوان‌ها سقف محتوا نیستند؛ پاسخ کوچک را با عنوان‌بندی زیاد سنگین نکن. مسیر کلی بده، اما چک‌لیستِ مرحله‌های آینده را بدون درخواست کاربر باز نکن.

## نمونهٔ بخش منابع برای دستیار تلگرام

**ارتباط با دوره:**
- جلسهٔ ۲، ML و یادگیری عمیق — تبدیل گفتار به متن با ASR.
- جلسهٔ ۳، API تا RAG — اتصال سرویس‌ها و خروجی ساختاریافته.
- جلسهٔ ۴، Agent — تفاوت Workflow و Agent، ابزار و تأیید انسانی.
- جلسهٔ ۵، مدل باز — سنجش API ابری در برابر اجرای محلی.

این نمونه ثابت نیست. فقط موردهایی را نگه دار که در پاسخ واقعی استفاده شده‌اند.

## وقتی انتخاب اصلی مبهم است

یک جمله برداشت موقت؛ حداکثر سه سؤال تصمیم‌ساز؛ در صورت مفیدبودن یک مسیر شرطی کوتاه. چک‌لیست نهایی نساز. به جای درخواست تمام فایل‌ها یا پرسش دربارهٔ همهٔ قیدها، فقط اطلاعاتی را بخواه که انتخاب را تغییر می‌دهند.

## وقتی شرایط تغییر کرده است

تغییر مؤثر را در یک جمله بگو؛ مسیر و بندهای متأثر را اصلاح کن و بقیه را تکرار نکن. وضعیت انجام‌شدن را از گفتهٔ کاربر جدا از صحت فنی نگه دار.

## نمونهٔ شکل بند

«متن مرجع صوت‌ها را قبل از مقایسه تثبیت کن — تکمیل وقتی: برای هر صوت، یک مرجع تأییدشده و یک قاعدهٔ نرمال‌سازی مشخص باشد.»

این صرفاً نمونهٔ نگارش است، نه بند اجباری همهٔ پروژه‌ها.
