# جلسهٔ ۵ — مدل‌های متن‌باز و LLM محلی

## چه وقت این مرجع را بخوان

برای Open Weight، مجوز، اجرای محلی، API یا Local، حافظه، Quantization، GGUF، Runtime، سخت‌افزار، Serving، Fine-tune، RLHF، Harness و چک‌لیست‌های نهایی.

## قواعد تصمیم‌ساز

- Open Weight با Open Source یکسان نیست. مجوز نسخه دقیق مدل و مشتق آن را بخوان.
- اجرای محلی برای داده حساس، آفلاین، کنترل نسخه، Data Residency یا بار پایدار مطرح است؛ پیش‌فرض همه پروژه‌ها نیست.
- هزینه محلی شامل سخت‌افزار، برق، خنک‌سازی، امنیت، نگهداری و زمان تیم است.
- رتبه عمومی مدل تصمیم نهایی نیست. مدل را روی Golden Set، زبان هدف و Tool Calling پروژه آزمایش کن.
- نام مدل ممکن است خانواده، اندازه، Dense یا MoE، Base یا Instruct، Quantization و Context را نشان دهد؛ Model Card مرجع تصمیم است.
- حافظه شامل وزن، KV Cache، Context، Batch و سربار Runtime است. جا شدن مدل را بدون آزمایش تضمین نکن.
- Quantization میان کیفیت، حافظه و سرعت توازن ایجاد می‌کند. سطح Q4 یا Q5 فقط نقطه شروع آزمایش است.
- Ollama و LM Studio برای نمونه اولیه ساده‌اند؛ llama.cpp کنترل بیشتر می‌دهد؛ vLLM و SGLang برای Serving پرظرفیت و MLX-LM برای Apple Silicon مطرح‌اند. نسخه روز را بررسی کن.
- پهنای باند حافظه، ظرفیت RAM یا VRAM، Throughput و Latency را روی سخت‌افزار واقعی Benchmark کن.
- Fine-tune برای تغییر رفتار پایدار یا مهارت خاص است. RAG برای دانش متغیر مناسب‌تر است. GPU موجود به‌تنهایی دلیل Fine-tune نیست.
- Harness شامل Prompt، Context، ابزار، مجوز، Sandbox، Trace، Retry و Eval است؛ کیفیت Agent فقط کیفیت مدل نیست.
- فایل مدل را از منبع معتبر با Hash و قالب امن بگیر. سرویس محلی را بدون احراز هویت روی اینترنت باز نکن.
- هشت چک‌لیست پایانی دوره مسیر مسئله، معماری، مدل، پیاده‌سازی، امنیت، حریم خصوصی، ارزیابی و مرور را جمع‌بندی می‌کنند.
