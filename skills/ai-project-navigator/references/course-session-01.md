# جلسهٔ ۱ — داده، سوخت هر AI Agent

## چه وقت این مرجع را بخوان

برای منبع و قالب داده، EDA، Missing Value، Outlier، داده تکراری، Encoding، Scaling، Feature Engineering، Split، Leakage، BI یا داشبورد.

## قواعد تصمیم‌ساز

- نوع داده می‌تواند جدولی، متن، تصویر، صوت، ویدیو، سری زمانی، مکانی یا گراف باشد. مدل و معیار باید با نوع داده سازگار باشند.
- قالب فایل را با ساختار، حجم، سرعت خواندن، سازگاری و امنیت انتخاب کن. Pickle و قالب اجرایی ناشناس ریسک دارند.
- Metadata و Data Dictionary برای فهم منبع، ستون، واحد، مجوز و تاریخ داده لازم‌اند.
- پیش از مدل، EDR و EDA انجام بده: نوع ستون، Missing، تکراری، Outlier، توزیع، رابطه و کیفیت برچسب.
- Missing ممکن است MCAR، MAR یا MNAR باشد؛ حذف یا Imputation را بدون شناخت سازوکار انتخاب نکن.
- Outlier می‌تواند خطا یا رویداد واقعی باشد. پیش از حذف، منبع آن را بررسی کن.
- Encoding و Scaling به مدل وابسته‌اند. تبدیل آموختنی را فقط روی Train برازش بده.
- Feature Engineering باید از دانش دامنه و داده در دسترس زمان پیش‌بینی استفاده کند.
- Split باید با زمان، فرد، مشتری، گوینده یا گروه سازگار باشد. Test را برای تنظیم مدل مصرف نکن.
- Data Leakage می‌تواند از آینده، Target، پیش‌پردازش یا نمونه‌های مرتبط وارد شود.
- KPI و نمودار باید به یک تصمیم کمک کنند. داشبورد شلوغ جای سؤال روشن را نمی‌گیرد.
- در RAG و Agent نیز کیفیت Chunk، Metadata، خروجی ابزار و داده ارزیابی اهمیت دارد.
