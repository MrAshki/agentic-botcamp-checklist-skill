# جلسهٔ ۳ — از API تا RAG

## چه وقت این مرجع را بخوان

برای معماری محصول، POC تا Product، Frontend، Backend، API، OAuth، پایگاه داده، مدل آنلاین یا محلی، محدودیت LLM، RAG، Embedding، Vector DB و استناد.

## قواعد تصمیم‌ساز

- محصول AI فقط مدل نیست؛ Frontend، API، داده، امنیت، مشاهده‌پذیری و عملیات نیز دارد.
- POC امکان فنی را می‌سنجد، Prototype تجربه را نشان می‌دهد، MVP ارزش اولیه را می‌آزماید و Product به پایداری و پشتیبانی نیاز دارد.
- API قرارداد ارتباط است. Method، Endpoint، احراز هویت، Schema، پاسخ و خطا باید روشن باشند.
- Secret فقط در Backend و محیط امن نگه داشته شود؛ نه در Frontend یا مخزن.
- API در برابر مدل محلی را با کیفیت، هزینه، تأخیر، حریم خصوصی، محل داده و توان عملیات انتخاب کن.
- LLM ممکن است دانش تازه یا خصوصی نداشته باشد، Hallucination کند یا منبع ندهد.
- RAG برای دانش بیرونی، تازه، خصوصی یا قابل‌استناد مناسب است؛ هر پروژه LLM به RAG نیاز ندارد.
- مرحله Offline شامل انتخاب سند مجاز، استخراج متن و Metadata، Chunking، Embedding و Index است.
- مرحله Online شامل اعتبارسنجی پرسش، بازیابی، فیلتر دسترسی، ساخت Context، تولید پاسخ و استناد است.
- Vector DB به‌تنهایی کیفیت RAG را تضمین نمی‌کند. Chunking، Metadata، مدل embedding، فیلتر و ارزیابی اثر دارند.
- داده بازیابی‌شده نامطمئن است و نباید دستور سیستم تلقی شود.
- اگر شاهد کافی نیست، سیستم باید نبود شاهد را اعلام کند.
- واقعیت داده، شاهد پژوهشی و تفسیر مدل را جدا نمایش بده.
