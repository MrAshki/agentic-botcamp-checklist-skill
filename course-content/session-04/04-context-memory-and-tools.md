# Context، حافظه و ابزار

## Context Engineering

Context Engineering یعنی انتخاب و چیدمان اطلاعاتی که در هر قدم وارد پنجره مدل می‌شوند. Context فقط Prompt نیست.

اجزای Context می‌توانند شامل این موارد باشند:

- System Prompt
- تعریف ابزارها
- سندهای بازیابی‌شده
- حافظه مرتبط
- تاریخچه لازم
- وظیفه فعلی

چهار عمل مطرح‌شده:

- Write: اطلاعات مفید را بیرون از پنجره مدل ذخیره کنید.
- Select: فقط اطلاعات مرتبط را انتخاب کنید.
- Compress: اطلاعات طولانی را فشرده یا خلاصه کنید.
- Isolate: Context نقش‌ها یا کارهای مستقل را جدا نگه دارید.

Context Rot زمانی رخ می‌دهد که پنجره با داده کم‌ربط یا زیاد پر شود و کیفیت تصمیم افت کند.

## حافظه و State

- Working Memory: اطلاعات موقت همان وظیفه یا گفت‌وگو
- Long-term Memory: ترجیحات، واقعیت‌های پایدار یا تجربه‌های گذشته
- Semantic Memory: دانش و واقعیت‌ها
- Episodic Memory: رویدادها و تجربه‌های قبلی
- Procedural Memory: روش انجام کار
- State: وضعیت ساختاریافته اجرای فعلی
- Checkpoint: ذخیره State برای ادامه، بازیابی یا بازگشت

همه چیز نباید در حافظه ذخیره شود. اطلاعات حساس، داده کم‌اعتبار، خطای مدل و محتوای تزریق‌شده می‌توانند Memory Poisoning ایجاد کنند. حافظه باید منبع، زمان، دامنه دسترسی و امکان حذف داشته باشد.

## Function Calling

مدل نام ابزار و آرگومان‌های ساختاریافته را پیشنهاد می‌دهد. برنامه آرگومان‌ها را اعتبارسنجی می‌کند و سپس ابزار را اجرا می‌کند.

اصل طراحی ابزار:

- نام و توضیح روشن
- ورودی محدود و Schema دقیق
- کمترین سطح دسترسی
- خروجی ساختاریافته
- Timeout و مدیریت خطا
- Idempotency برای عملیات قابل‌تکرار
- تفکیک عملیات خواندن از نوشتن
- تأیید کاربر برای عمل حساس یا برگشت‌ناپذیر

## MCP

Model Context Protocol یک استاندارد برای اتصال Client به Serverهای ابزار و منبع است. Server می‌تواند Tool، Resource یا Prompt ارائه کند.

MCP به‌خودی‌خود ابزار را امن نمی‌کند. Server شخص ثالث باید مانند کد شخص ثالث بررسی شود. مجوزها، داده خروجی، عملیات نوشتن و مسیر Secret باید محدود باشند.

A2A برای ارتباط Agent با Agent مطرح می‌شود؛ MCP بیشتر اتصال Agent یا برنامه به ابزار و Context را استاندارد می‌کند.
