# مطالعه موردی: دستیار صوتی فارسی

## هدف

کاربر در تلگرام پیام صوتی فارسی می‌فرستد. سامانه صوت را به متن تبدیل می‌کند، Intent را تشخیص می‌دهد و یکی از کارهای زمان‌بندی یا ارسال ایمیل را آماده می‌کند. عملیات نوشتن فقط پس از تأیید کاربر اجرا می‌شود.

## مرز نسخه آموزشی

- یک کاربر یا Allowlist محدود
- دو Intent اصلی: ساخت رویداد و ارسال ایمیل
- خروجی JSON ساختاریافته
- تاریخ و منطقه زمانی صریح
- تأیید پیش از اجرای عمل بیرونی
- ثبت Audit بدون محتوای حساس

## مشخصات فنی نمونه

- Telegram Bot برای دریافت پیام
- STT برای تبدیل صوت فارسی به متن
- DeepSeek به‌عنوان Provider مدل
- Google Calendar برای رویداد
- Resend برای ایمیل
- FastAPI و MCP برای Backend و ابزارها
- PostgreSQL برای پیام، State و Audit
- Docker Compose برای اجرای اجزا
- داشبورد ساده برای Token، هزینه، تأخیر و کیفیت

این فهرست معماری اجباری نیست. سرویس‌ها می‌توانند با گزینه مناسب پروژه جایگزین شوند.

## مسیر پنج‌مرحله‌ای ساخت

### ۱. زیرساخت

- فایل `SPEC.md`
- Docker Compose
- ربات تلگرام
- پایگاه داده و مدل‌های اصلی
- ماژول ایمیل
- Secret فقط در فایل محیطی

### ۲. Workflow ایجنتی

- تبدیل صوت به متن
- تشخیص Intent و استخراج پارامتر
- نمایش پیش‌نمایش فارسی
- تأیید یا لغو
- فراخوانی ابزار تقویم یا ایمیل
- State و حافظه محدود و قابل‌حذف

### ۳. API و MCP

- Endpointهای سلامت، Telegram و عملیات ادمین
- ابزارهای تقویم و ایمیل با Schema مشخص
- محدودیت دسترسی و خطای ساختاریافته
- OpenAPI و آزمون Endpointها

### ۴. داشبورد کیفیت

- مصرف Token و هزینه
- تأخیر و نرخ خطا
- موفقیت Intent و Tool Call
- نتیجه Golden Set
- فیلتر بازه زمانی و خروجی CSV

### ۵. یکپارچه‌سازی و استقرار

- آزمون کامل صوت تا عمل تأییدشده
- اجرای Golden Set
- تنظیم HTTPS، دامنه و Secret
- استقرار با Docker Compose
- Health Check، Log و Backup
- ثبت محدودیت‌ها و موارد بررسی‌نشده

## خطرهای مهم

- نام یا آدرس اشتباه در ایمیل
- تاریخ مبهم یا منطقه زمانی نادرست
- اجرای تکراری پس از Retry
- ذخیره ناخواسته متن یا صوت شخصی
- افشای Token ربات، Google یا سرویس ایمیل
- اعتماد بیش‌ازحد به خروجی STT یا مدل

برای کنترل این خطرها، پیش‌نمایش، تأیید، Idempotency، حداقل نگهداری داده و Audit لازم است.
