# مفاهیم اصلی Agentic AI

## Workflow یا Agent

Workflow مسیر ازپیش‌تعریف‌شده‌ای است که در آن مراحل و شاخه‌ها را برنامه‌نویس مشخص می‌کند. Agent از مدل برای تصمیم‌گیری درباره قدم بعدی استفاده می‌کند.

نردبان پیچیدگی جلسه:

1. LLM ساده
2. LLM تقویت‌شده با RAG، ابزار یا حافظه
3. Workflow با مسیرهای مشخص
4. Agent با انتخاب پویای ابزار و مسیر
5. Multi-Agent برای نقش‌های واقعا مستقل

قاعده دوره این است که از ساده‌ترین راه‌حل قابل‌ارزیابی شروع کنید. اگر Workflow ثابت مسئله را حل می‌کند، Agent خودمختار ارزش افزوده ندارد.

## آناتومی Agent

اجزای اصلی:

- Model برای فهم، استدلال و تصمیم
- Instructions برای هدف و محدودیت
- Knowledge شامل داده، سند و RAG
- Memory و State برای اطلاعات لازم در طول کار
- Tools برای اقدام در سامانه بیرونی
- Guardrails برای کنترل ورودی، خروجی و عمل

حلقه ReAct:

1. Observe: ورودی، Context و نتیجه ابزار را ببیند.
2. Think: قدم بعدی را تعیین کند.
3. Act: ابزار یا عملیات مشخص را اجرا کند.
4. نتیجه را مشاهده کند و حلقه را تا پایان یا سقف مجاز ادامه دهد.

حلقه باید سقف قدم، Timeout، بودجه Token و شرط توقف داشته باشد.

## معماری نمونه جلسه

نمونه اصلی یک دستیار شخصی فارسی است:

```text
پیام صوتی تلگرام
  -> تبدیل گفتار به متن
  -> Agent و خروجی ساختاریافته
  -> ابزار تقویم یا ایمیل
  -> پاسخ و ثبت Audit
```

اجزای نمونه شامل Telegram Bot، سرویس STT، مدل DeepSeek، FastAPI، PostgreSQL، Google Calendar و Resend هستند. این فناوری‌ها نمونه‌اند و الزام معماری نیستند.

## تصمیم‌گیری ساختاریافته

خروجی مدل باید به Schema محدود شود. برای نمونه، Intent، پارامترها، نیاز به تأیید و پیام پاسخ در JSON مشخص می‌شوند. کد برنامه باید Schema را اعتبارسنجی کند و فقط عملیات مجاز را اجرا کند.

مدل نباید مستقیم به همه ابزارها، کلیدها یا داده‌ها دسترسی داشته باشد.
