# انتخاب مسئله و مدل

## پرسش‌های پیش از انتخاب مدل

1. خروجی موردنیاز عدد، برچسب، گروه، ناهنجاری، متن، تصویر یا عمل است؟
2. داده برچسب‌دار است؟
3. داده جدولی، متن، تصویر، صوت، دنباله یا گراف است؟
4. هزینه خطا چیست و کدام نوع خطا مهم‌تر است؟
5. توضیح‌پذیری، زمان پاسخ، بودجه و سخت‌افزار چه محدودیتی دارند؟

## مسیر پیشنهادی دوره

### داده جدولی و برچسب‌دار

- برای خط پایه و توضیح‌پذیری: Linear یا Logistic Regression
- برای رابطه‌های غیرخطی و مقاومت مناسب: Random Forest
- برای دقت بالاتر روی بسیاری از داده‌های جدولی: XGBoost یا LightGBM
- برای داده کوچک: KNN، Naive Bayes یا SVM را نیز بررسی کنید.

### متن

- خط پایه: TF-IDF با Logistic Regression یا Naive Bayes
- داده برچسب‌دار و نیاز به بهبود: مدل زبانی ازپیش‌آموزش‌دیده مانند ParsBERT را ارزیابی کنید.
- بدون داده برچسب‌دار: یک LLM آماده را با نمونه واقعی و معیار مشخص آزمایش کنید.
- جست‌وجو یا شباهت: embedding به‌همراه نزدیک‌ترین همسایه‌ها یا بازیابی

### تصویر و صوت

- داده برچسب‌دار کم: انتقال یادگیری با مدل ازپیش‌آموزش‌دیده
- تشخیص یا بخش‌بندی: خانواده مدل متناسب با همان وظیفه
- تبدیل گفتار به متن: مدل ASR آماده، پس از آزمون روی زبان و شرایط صوتی واقعی

### داده بدون برچسب

- خوشه‌ها: K-Means یا DBSCAN
- کاهش بُعد و نمایش: PCA، UMAP یا t-SNE
- ناهنجاری: Isolation Forest یا Autoencoder، متناسب با پیچیدگی داده

### تصمیم‌های دنباله‌ای

- بازخورد ساده: Bandit
- کنترل محیط: الگوریتم‌های RL مانند Q-Learning یا PPO
- رفتار LLM: روش هم‌ترازی فقط در صورت وجود مسئله، داده، بودجه و معیار مناسب
- کار چندمرحله‌ای با ابزار: LLM به‌همراه Workflow یا Agent، نه الزاماً آموزش مدل

## قانون‌های عملی

- ساده‌ترین مدل قابل‌اندازه‌گیری را ابتدا بسازید.
- مدل‌ها را روی داده خودتان مقایسه کنید. رتبه عمومی جای ارزیابی پروژه را نمی‌گیرد.
- مدل پیچیده‌تر باید بهبود قابل‌سنجش و ارزش عملی داشته باشد.
- نبود برچسب یا سخت‌افزار به‌تنهایی نقص پروژه نیست. مسیر باید با محدودیت واقعی سازگار شود.
- استفاده از مدل آماده، API یا مدل محلی یک تصمیم مهندسی است. حریم خصوصی، هزینه، تأخیر، نگهداری و مجوز را با هم بسنجید.
- Fine-tune، GPU و معماری عمیق پیش‌فرض نیستند.
