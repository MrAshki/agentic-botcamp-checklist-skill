# ارزیابی، تعمیم و تولید

## Underfitting و Overfitting

- Underfitting: مدل روی آموزش و آزمون ضعیف است. علت می‌تواند مدل بیش‌ازحد ساده، ویژگی ناکافی، منظم‌سازی زیاد یا آموزش ناکافی باشد.
- Overfitting: مدل روی آموزش خوب و روی داده ندیده ضعیف است. راهکارها شامل داده بیشتر، منظم‌سازی، Dropout، Early Stopping، افزایش داده، مدل ساده‌تر یا Ensemble هستند.
- هدف، تعمیم به داده ندیده است؛ نه بیشینه‌کردن نتیجه روی داده آموزش.

## تقسیم داده و اعتبارسنجی

- داده آموزش برای یادگیری وزن‌ها است.
- داده اعتبارسنجی برای انتخاب مدل و ابرپارامتر است.
- داده آزمون برای سنجش نهایی است و نباید بارها برای تصمیم‌گیری استفاده شود.
- Stratified K-Fold نسبت کلاس‌ها را حفظ می‌کند.
- Group K-Fold از پخش‌شدن اعضای یک گروه میان تقسیم‌ها جلوگیری می‌کند.
- TimeSeriesSplit ترتیب زمان را حفظ می‌کند.
- Pipeline باید پیش‌پردازش و مدل را یکجا کنترل کند تا نشت داده کم شود.

## تنظیم ابرپارامتر

- Grid Search همه ترکیب‌های تعریف‌شده را بررسی می‌کند.
- Random Search زیرمجموعه‌ای تصادفی را بررسی می‌کند.
- Bayesian Optimization از نتیجه‌های قبلی برای انتخاب آزمایش بعدی استفاده می‌کند.

بودجه محاسباتی و زمان باید دامنه جست‌وجو را محدود کنند.

## معیارهای دسته‌بندی

- Accuracy: سهم پیش‌بینی درست؛ برای کلاس نامتوازن کافی نیست.
- Precision: چه سهمی از مثبت‌های پیش‌بینی‌شده درست بوده‌اند.
- Recall: چه سهمی از مثبت‌های واقعی پیدا شده‌اند.
- F1: میانگین هارمونیک Precision و Recall.
- ROC-AUC و PR-AUC: کیفیت رتبه‌بندی در آستانه‌های مختلف؛ PR-AUC برای کلاس مثبت کمیاب مهم است.

در مسئله‌هایی مانند کشف تقلب یا بیماری، از دست‌دادن مورد مثبت ممکن است Recall را مهم کند. در برخی فیلترها، مثبت کاذب ممکن است Precision را مهم‌تر کند. Macro و Weighted F1 در داده نامتوازن برداشت متفاوتی می‌دهند.

## معیارهای رگرسیون

- MAE: خطای میانگین با واحد اصلی خروجی و حساسیت کمتر به خطاهای بسیار بزرگ
- MSE: جریمه بیشتر برای خطاهای بزرگ
- RMSE: ریشه MSE با واحد اصلی خروجی
- MAPE: درصد خطا، اما نزدیک صفر مشکل دارد
- R²: میزان توضیح واریانس نسبت به خط پایه
- Huber و Quantile Loss: گزینه‌های مناسب برای نیازهای خاص

همیشه نتیجه را با یک Baseline ساده مقایسه کنید و باقی‌مانده‌ها را بررسی کنید.

## توضیح‌پذیری

Feature Importance، Permutation Importance، SHAP، LIME، Grad-CAM و Attention Map ابزارهای مطرح جلسه هستند. انتخاب روش به مدل، داده و نیاز کاربر بستگی دارد. توضیح تولیدشده باید با محدودیت‌های روش تفسیر شود.

## استقرار و پایش

- ذخیره مدل: قالب متناسب با کتابخانه، ONNX یا `save_pretrained`
- سرویس‌دهی: Batch یا Real-time، مانند API در Docker
- کاهش هزینه: Quantization یا Distillation در صورت نیاز واقعی
- نسخه‌بندی و ثبت آزمایش: ابزارهایی مانند MLflow و DVC
- پایش: Data Drift، Concept Drift، افت معیار، نیاز به آموزش مجدد و Bias

در سیستم Agentic، تغییر نسخه مدل یا ابزار و تغییر پاسخ API نیز نوعی Drift است. Tracing و مجموعه ارزیابی ثابت برای تشخیص پس‌رفت لازم‌اند.
