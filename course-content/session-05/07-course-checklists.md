# هشت چک‌لیست پایانی دوره

این فایل محتوای صفحه‌های ۲۷ تا ۳۴ را به‌شکل ساختاریافته ثبت می‌کند. برچسب‌های جلسه در نسخه نهایی منابع باید با نام رسمی جلسه‌ها نمایش داده شوند.

## چک‌لیست ۱: مدل‌سازی مسئله واقعی

### مسئله و ارزش

- تصمیمی که بهتر می‌شود، KPI و هزینه خطا را مشخص کنید.
- Baseline بدون AI را ثبت کنید.
- محدودیت بودجه، تأخیر، حریم خصوصی، قانون و تحریم را بنویسید.
- AI را فقط جایی اضافه کنید که ارزش قابل‌سنجش دارد.

### نوع مسئله

- عدد: رگرسیون
- دسته: دسته‌بندی
- بدون برچسب: خوشه‌بندی یا روش بدون‌نظارت
- داده جدولی: ابتدا مدل کلاسیک
- تصویر، صوت یا گراف: معماری متناسب با داده
- تولید و استخراج: LLM
- مسیر ثابت چندمرحله‌ای: Workflow
- قدم‌های نامعلوم: Agent

### داده، مدل و عملیات

- منبع، مجوز، حجم و کیفیت داده را پیش از مدل بسنجید.
- Train، Validation و Test را جدا کنید و Data Leakage را کنترل کنید.
- از ساده‌ترین مدل شروع کنید.
- معیار متناسب با مسئله انتخاب کنید.
- استقرار، نسخه‌بندی، Rollback و پایش را از ابتدا در نظر بگیرید.
- برای عمل پرخطر یا برگشت‌ناپذیر تأیید انسان بگیرید.

## چک‌لیست ۲: انتخاب معماری

- داده جدولی برچسب‌دار: رگرسیون، Random Forest یا XGBoost
- تصویر، صوت، گراف یا سری زمانی: معماری تخصصی و مدل آماده
- متن ثابت و پرحجم: مدل کوچک یا Fine-tune در صورت اثبات نیاز
- دانش خصوصی یا به‌روز: RAG
- سبک تکراری که RAG حل نمی‌کند: Fine-tune
- مسیر ثابت چندمرحله‌ای: Chaining، Routing یا Parallelization
- تعداد قدم نامعلوم: Agent با ابزار، حافظه و سقف قدم
- نقش‌ها و دسترسی‌های متفاوت: Multi-Agent فقط با دلیل روشن
- داده حساس و مدل قوی: معماری ترکیبی یا Gateway

قانون طلایی: ساده‌ترین راهی که کار می‌کند. هر پله پیچیدگی باید با ارزیابی توجیه شود.

## چک‌لیست ۳: انتخاب مدل

- کیفیت را روی Golden Set خودتان بسنجید.
- Tool Calling و JSON پایدار را آزمایش کنید.
- کیفیت فارسی را جدا بررسی کنید.
- Context کافی، هزینه هر وظیفه و تأخیر P95 را بسنجید.
- مجوز، حریم خصوصی، محل داده و پایداری Provider را بررسی کنید.
- API برای شروع سریع و بار نامنظم مناسب است.
- مدل محلی برای داده حساس، آفلاین، حجم پایدار یا کنترل نسخه مطرح است.
- حافظه تقریبی، KV Cache و پهنای باند را برآورد کنید.
- Quantization را با آزمون کیفیت انتخاب کنید.

## چک‌لیست ۴: پیاده‌سازی و استقرار

- `SPEC.md` یا `AGENTS.md` را پیش از کدنویسی آماده کنید.
- کار را به پرامپت‌ها یا تغییرهای کوچک تقسیم کنید.
- پس از هر قدم Commit و آزمون انجام دهید.
- Secret را در مخزن قرار ندهید.
- خروجی LLM را با Schema محدود کنید.
- Timeout، Retry، Backoff، Idempotency و سقف هزینه تعریف کنید.
- برای RAG، Metadata، Chunking، بازیابی و استناد را جدا کنترل کنید.
- Log، Health Check، Trace، بودجه، Backup، Rollout و Kill Switch داشته باشید.

## چک‌لیست ۵: دفاع، ایمنی و امنیت

- Prompt Injection مستقیم و غیرمستقیم را فرض کنید.
- داده خصوصی، محتوای نامطمئن و ارتباط بیرونی را ترکیب پرخطر بدانید.
- ورودی را اعتبارسنجی و متن پنهان را بررسی کنید.
- ابزار را با Allowlist، Schema، کمترین دسترسی و کلید جدا محدود کنید.
- اجرا را با Sandbox، Timeout، Rate Limit و سقف قدم کنترل کنید.
- خروجی را برای Schema، سیاست و PII بررسی کنید.
- عمل حساس را با تأیید انسان، Audit و Kill Switch محافظت کنید.
- مدل محلی را از منبع معتبر، با Hash و قالب امن دریافت کنید.

## چک‌لیست ۶: حریم خصوصی، قانون و اخلاق

- حداقل داده لازم را جمع‌آوری کنید.
- PII را پیش از ارسال به API Mask کنید.
- رضایت، هدف مشخص، دوره نگهداری و حذف را تعریف کنید.
- Data Residency و قرارداد پردازش را بررسی کنید.
- مجوز مدل، داده و خروجی را جدا بخوانید.
- Bias را برای گروه‌های مختلف بسنجید.
- امکان اعتراض و بازبینی انسانی فراهم کنید.
- محدودیت سامانه را صادقانه اعلام کنید.
- قوانین حوزه فعالیت را با مسئول حقوقی بررسی کنید.

## چک‌لیست ۷: ارزیابی و کیفیت مداوم

- برای ML، معیار متناسب با نوع مسئله و هزینه خطا انتخاب کنید.
- Cross-Validation، Test نهایی، Overfitting، Bias و Drift را کنترل کنید.
- برای LLM و Agent، Golden Set را در CI اجرا کنید.
- Unit، Trajectory، Outcome، Safety و Human Review را جدا بسنجید.
- Tool Calling، پایداری، تعداد قدم، Token و هزینه را ثبت کنید.
- کیفیت Production را با بازخورد، خطا، تأخیر، هزینه و بازبینی نمونه‌های واقعی پایش کنید.
- هر تغییر مدل یا Prompt باید از دروازه ارزیابی و انتشار مرحله‌ای عبور کند.

## چک‌لیست ۸: مرور کل دوره

مسیر دوره:

```text
مسئله و ارزش
  -> داده
  -> مدل
  -> LLM و Agent
  -> RAG
  -> مدل باز و استقرار
```

سه سؤال پایانی برای هر پروژه:

1. ارزش و Baseline روشن است؟
2. با ارزیابی ثابت کرده‌ایم بهتر است؟
3. اگر خطا کند، آسیب محدود است و انسان می‌تواند مداخله کند؟

برای Demo Day، یک روایت روشن، نمونه قابل‌اجرا، مستندات و محدودیت‌های صریح آماده کنید.
