# یادداشت بررسی جلسه ۵

## وضعیت استخراج

- تعداد صفحه PDF: ۳۴
- استخراج متن: انجام شد
- رندر تصویری همه صفحه‌ها: انجام شد
- بررسی تصویری همه صفحه‌ها در شش Contact Sheet: انجام شد
- نمایه صفحه‌به‌صفحه: تکمیل شد
- چک‌لیست‌های ۱ تا ۸: جداگانه ثبت شدند
- تغییر در اسکیل: انجام نشد

## کیفیت منبع

- همه صفحه‌ها درست رندر شدند.
- جدول‌ها، نمودارها، فرمول‌های تقریبی و چک‌لیست‌ها خوانا هستند.
- متن انگلیسی و کد در استخراج خام مناسب است.
- ترتیب بخشی از متن فارسی در استخراج خام به‌هم‌ریخته است. محتوای فارسی با تصویر صفحه تطبیق داده شد.
- هشدارهای FontBBox و Type 3 Glyph بر خوانایی اثر نگذاشتند.

## مرز محتوا و تفسیر

- مفاهیم مجوز، مدل باز، Quantization، حافظه، Runtime، سخت‌افزار، Serving و امنیت از محتوای دوره استخراج شدند.
- گروه‌بندی فایل‌ها یک جمع‌بندی ساختاری است.
- قیمت API، قیمت سخت‌افزار، رتبه مدل و نام نسخه‌ها نباید به‌عنوان داده پایدار استفاده شوند.
- ابزار یا مدل محلی فقط وقتی پیشنهاد می‌شود که محدودیت داده، هزینه، آفلاین یا کنترل نسخه آن را توجیه کند.

## موارد زمان‌حساس

این موارد باید پیش از ورود به اسکیل یا توصیه عملی با منبع روز بررسی شوند:

- مجوز و Model Card هر مدل
- قیمت API و سخت‌افزار
- Leaderboardها و کیفیت مدل‌ها
- نسخه و قابلیت Ollama، llama.cpp، LM Studio، vLLM، SGLang و MLX-LM
- فرمان‌های نصب OpenCode و پیکربندی Provider
- مشخصات GPU، NPU و حافظه دستگاه‌ها
- روش‌های RLHF و هم‌ترازی

## نکات مناسب برای ادغام آینده با اسکیل

- API یا Local یک تصمیم مبتنی بر محدودیت است، نه ترجیح ثابت.
- نبود GPU به‌تنهایی مانع پروژه نیست.
- Quantization و مدل کوچک باید پیش از خرید سخت‌افزار آزمایش شوند.
- هزینه کل مالکیت باید با هزینه API مقایسه شود.
- Ranking عمومی باید با Golden Set پروژه کنترل شود.
- Fine-tune و RLHF فقط با نیاز، داده و معیار روشن مطرح شوند.
- Harness، ارزیابی و امنیت به‌اندازه مدل اهمیت دارند.
- چک‌لیست‌های ۱ تا ۸ باید با نام رسمی جلسه‌ها و موضوع استفاده‌شده ارجاع داده شوند.

## موردی که در این مرحله انجام نشد

این محتوا هنوز با فایل‌های جلسه‌های دیگر و چک‌لیست مرجع نهایی ترکیب نشده است. این کار در مرحله بعدی و پس از تأیید کاربر انجام می‌شود.
