# پروژه مالی و کدنویسی با مدل محلی

## دمو مالی چندنقشی

پروژه جلسه یک Workflow مالی با چهار نقش دارد:

1. Classifier سند را تشخیص و مسیردهی می‌کند.
2. Extraction داده‌های ساختاریافته مانند مبلغ و تاریخ را استخراج می‌کند.
3. Analyst شاخص‌ها و ریسک را تحلیل می‌کند.
4. Reviewer نتیجه، شواهد و محدودیت را بازبینی می‌کند.

همه نقش‌ها روی State مشترک کار می‌کنند. خروجی هر مرحله باید Schema داشته باشد. داده ساختگی است و سامانه تصمیم مالی واقعی نمی‌گیرد.

## استفاده از مدل محلی

مدل محلی می‌تواند برای Extraction یا طبقه‌بندی داده حساس استفاده شود. در اسلاید، پاسخ مدل به JSON محدود می‌شود و برنامه خروجی را Parse می‌کند.

نکات مهم:

- ورودی و خروجی باید اعتبارسنجی شوند.
- عدد، تاریخ و واحد پول با کد قطعی کنترل شوند.
- مدل نباید تصمیم نهایی مالی بگیرد.
- خطا یا مقدار نامطمئن باید برای بازبینی علامت‌گذاری شود.
- نتیجه مدل باید با Baseline یا مدل API روی Golden Set مقایسه شود.

## OpenCode و Ollama

نمونه جلسه اتصال یک Code Agent به API محلی Ollama را نشان می‌دهد. مراحل عمومی:

1. Ollama یا Runtime محلی نصب و اجرا شود.
2. مدل مناسب دریافت شود.
3. Endpoint محلی با یک درخواست ساده آزمایش شود.
4. Provider محلی در Code Agent تعریف شود.
5. مدل و Context Limit صحیح تنظیم شوند.
6. یک کار کوچک و قابل‌بازبینی اجرا شود.

فرمان نصب و فایل پیکربندی زمان‌حساس هستند. پیش از انتشار باید با مستندات رسمی نسخه فعلی تطبیق داده شوند.

## ابزارها و پروژه‌های معرفی‌شده

جلسه نمونه‌هایی مانند JEV، Whisper، Open WebUI، LangGraph، smolagents، Unsloth، Streamlit، AnythingLLM، Docling، Hermes، Obsidian و Devin را معرفی می‌کند. هدف، شناخت دسته ابزارها است؛ نه الزام استفاده از همه آن‌ها.

برای هر ابزار باید نیاز، مجوز، نگهداری، امنیت و هزینه بررسی شود.
