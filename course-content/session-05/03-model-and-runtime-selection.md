# انتخاب مدل، Quantization و Runtime

## خواندن نام مدل

نام مدل ممکن است این اطلاعات را نشان دهد:

- خانواده و نسل
- تعداد پارامتر
- Dense یا MoE
- Base، Instruct یا Chat
- نوع Fine-tune یا ترجیح رفتاری
- Quantization و قالب فایل
- Context Length
- کاربرد مانند Coder، Vision یا Embedding

نام مدل تضمین کیفیت، ایمنی یا سازگاری نیست. Model Card و مجوز باید بررسی شوند.

## Dense و MoE

در مدل Dense همه وزن‌ها در هر Token فعال‌اند. در Mixture of Experts فقط بخشی از Expertها برای هر Token فعال می‌شوند. MoE می‌تواند ظرفیت کل بالا و محاسبه فعال کمتر داشته باشد، اما همه وزن‌ها همچنان باید در حافظه یا مسیر ذخیره‌سازی مناسب قرار گیرند.

## برآورد حافظه

حافظه فقط وزن مدل نیست. اجزای اصلی:

- وزن‌ها
- KV Cache
- Context و Batch
- Buffer و سربار Runtime
- حافظه موقت محاسبه

قاعده تقریبی وزن:

```text
حافظه وزن ≈ تعداد پارامتر × بیت هر وزن ÷ ۸
```

سپس سربار Runtime و KV Cache اضافه می‌شود. Context طولانی و هم‌زمانی بیشتر می‌توانند حافظه را به‌طور محسوس افزایش دهند.

## GGUF و Quantization

GGUF یک قالب رایج برای اجرای مدل با خانواده llama.cpp است. Quantization دقت عددی وزن‌ها را کم می‌کند تا حافظه و گاهی زمان بارگذاری کاهش یابد.

سطوحی مانند Q8، Q6، Q5، Q4، Q3 و Q2 توازن متفاوتی میان کیفیت، حافظه و سرعت دارند. مقدار کمتر همیشه سریع‌تر یا بهتر نیست. نوع سخت‌افزار و Kernel نیز اثر دارد.

برای شروع، یک Quantization متوسط مانند Q4 یا Q5 می‌تواند نقطه آزمایش باشد. کیفیت باید روی وظیفه واقعی سنجیده شود.

## انتخاب Runtime

- llama.cpp: کنترل زیاد، پشتیبانی GGUF و اجرای CPU/GPU
- Ollama: راه‌اندازی ساده و API محلی
- LM Studio: رابط گرافیکی برای آزمایش و مدیریت مدل
- vLLM: Serving با Throughput بالا و GPU
- SGLang: Serving و Workflowهای ساختاریافته با تمرکز بر کارایی
- MLX-LM: اجرای بهینه روی Apple Silicon

راهنمای کلی:

- نمونه اولیه ساده: Ollama یا LM Studio
- کنترل فنی و دستگاه متنوع: llama.cpp
- سرویس چندکاربره GPU: vLLM یا SGLang
- Apple Silicon: MLX-LM یا Runtime سازگار

این انتخاب‌ها زمان‌حساس هستند و باید با نسخه روز ابزار بررسی شوند.
