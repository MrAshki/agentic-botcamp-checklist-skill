# مفاهیم اصلی مدل‌های باز و اجرای محلی

## Open Source، Open Weight و Closed

- Open Source باید کد، وزن و شرایط استفاده روشن داشته باشد.
- Open Weight یعنی وزن مدل منتشر شده است، اما کد آموزش، داده یا همه جزئیات ممکن است باز نباشند.
- Closed یعنی وزن و فرایند آموزش در اختیار ارائه‌دهنده است و معمولا از راه API استفاده می‌شود.

انتشار وزن به‌تنهایی مجوز آزاد نمی‌سازد. مجوز هر مدل و هر نسخه باید جدا خوانده شود. مجوز مدل پایه ممکن است برای نسخه Fine-tune نیز محدودیت ایجاد کند.

## چرا اجرای محلی؟

دلیل‌های اصلی:

- داده نباید از محیط خارج شود.
- کنترل نسخه مدل مهم است.
- اجرای آفلاین لازم است.
- هزینه API در حجم بالا نامناسب است.
- Data Residency یا محدودیت سازمانی وجود دارد.
- تأخیر شبکه یا وابستگی به Provider قابل‌قبول نیست.

## هزینه‌های پنهان

- خرید یا اجاره سخت‌افزار
- برق، خنک‌سازی و فضا
- استقرار و نگهداری
- امنیت و به‌روزرسانی
- پایش و پاسخ به خطا
- زمان تیم فنی
- ظرفیت بلااستفاده در دوره‌های کم‌بار

اجرای محلی همیشه ارزان‌تر یا امن‌تر نیست. امنیت به نحوه استقرار، دسترسی و عملیات بستگی دارد.

## معیار تصمیم

مقایسه API و مدل محلی باید این موارد را پوشش دهد:

- کیفیت روی داده واقعی پروژه
- هزینه هر درخواست و هزینه کل مالکیت
- Latency و Throughput
- حریم خصوصی و محل نگهداری داده
- پایداری نسخه و قابلیت Rollback
- سخت‌افزار موجود
- توان تیم برای عملیات و امنیت
- مجوز استفاده

برای حجم کم یا پروژه کوتاه، API ممکن است منطقی‌تر باشد. برای داده بسیار حساس، آفلاین یا حجم پایدار بالا، اجرای محلی می‌تواند ارزش داشته باشد.

## جامعه و رتبه‌بندی

Hugging Face، Leaderboardها، LM Arena و جامعه‌هایی مانند LocalLLaMA منابع کشف مدل هستند. رتبه عمومی تصمیم نهایی نیست. مدل باید روی Golden Set همان پروژه، زبان هدف، Tool Calling و محدودیت سخت‌افزار آزمایش شود.
