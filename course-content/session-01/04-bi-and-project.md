# BI، نمودار، پروژه و تکلیف جلسه ۱

## از داده تا تصمیم

هدف تحلیل داده ساخت نمودار تزئینی نیست. هر تحلیل باید به یک سؤال کسب‌وکار پاسخ دهد.

چهار سطح تحلیل:

- Descriptive: چه شد؟
- Diagnostic: چرا شد؟
- Predictive: چه خواهد شد؟
- Prescriptive: چه کار کنیم؟

BI داده خام را به KPI، گزارش و داشبورد تبدیل می‌کند. تصمیم داده‌محور باید بر شواهد تکیه کند و نتیجه آن دوباره سنجیده شود.

## نوع داده پیش از نمودار

- Nominal: دسته بدون ترتیب
- Ordinal: دسته دارای ترتیب
- Text: متن آزاد
- Time: تاریخ یا Timestamp
- Continuous: مقدار عددی پیوسته
- Discrete: مقدار شمارشی

عددبودن ظاهر یک ستون به معنی کمی‌بودن آن نیست. کد پستی و شماره مشتری معمولا Nominal هستند.

## راهنمای انتخاب نمودار

| سؤال | نمودار پیشنهادی |
|---|---|
| مقایسه دسته‌ها | Bar یا Clustered Bar |
| سهم از کل | Pie یا Donut با حداکثر پنج بخش؛ Stacked Bar یا Treemap |
| روند در زمان | Line یا Area |
| توزیع یک متغیر | Histogram، Box یا Violin |
| رابطه دو متغیر | Scatter یا Bubble |
| رابطه چند متغیر | Heatmap یا Pair Plot |
| جغرافیا | Choropleth Map |
| مراحل و ریزش | Funnel یا Waterfall |
| یک عدد کلیدی | KPI Card |

## نکات نمودارهای اصلی

### Pie

- برای سهم از کل و دو تا پنج دسته مناسب است.
- برای مقایسه دقیق مناسب نیست.
- چند Pie کنار هم مقایسه را سخت می‌کند.

### Bar

- برای مقایسه عدد میان دسته‌ها مناسب است.
- محور عددی باید از صفر شروع شود.
- Clustered برای چند معیار در هر دسته است.
- Stacked ترکیب و کل هر دسته را هم‌زمان نشان می‌دهد.

### Histogram

- شکل توزیع، مرکز، پراکندگی و Outlier را نشان می‌دهد.
- نتیجه می‌تواند با تعداد Bin تغییر کند؛ چند مقدار را مقایسه کنید.

### Line

- برای روند و نوسان روی محور مرتب یا زمان مناسب است.
- داده زمانی باید در بازه مناسب تجمیع شود.
- خط برای دسته بدون ترتیب مناسب نیست.

### Scatter

- رابطه، خوشه و Outlier را نشان می‌دهد.
- رنگ یا اندازه می‌تواند متغیر سوم را اضافه کند.
- رابطه مشاهده‌شده علیت را ثابت نمی‌کند.

### Box

- median، Q1، Q3، دامنه و Outlier را خلاصه می‌کند.
- برای مقایسه توزیع بین دسته‌ها مناسب است.
- جعبه نشان‌دهنده ۵۰٪ میانی داده است، نه mean به‌علاوه و منهای انحراف معیار.

## قواعد طلایی داشبورد

1. مخاطب باید در پنج ثانیه وضعیت کلی را بفهمد.
2. KPIهای اصلی در بالای صفحه قرار بگیرند.
3. عنوان باید Insight را بگوید، نه فقط نام متغیرها را.
4. محور Bar از صفر شروع شود و مقیاس نمودارهای مقایسه‌ای یکسان باشد.
5. رنگ فقط برای معنا و هشدار استفاده شود.
6. نمودار کمتر و ساده‌تر بهتر است.
7. فیلتر و Drill-down از کل به جزء طراحی شوند.
8. داشبورد برای مخاطب مشخص ساخته شود.

## پروژه جلسه - داشبورد BI روی SuperStore

مراحل:

1. هر سه Sheet را با `sheet_name=None` وارد کنید.
2. EDR انجام دهید و نوع ستون، تاریخ، Missing و تکراری را اصلاح کنید.
3. Orders و Returns را روی `Order ID` ادغام کنید و `is_returned` بسازید.
4. `profit_margin`، `days_to_ship`، ماه و RFM مشتری را بسازید.
5. KPIها و نمودارها را محاسبه کنید. برای مقایسه Regionها Radar Chart نیز پیشنهاد شده است.
6. داشبورد را منتشر کنید و سه Insight بنویسید.

KPIهای پیشنهادی:

- Total Sales
- Total Profit
- Profit Margin
- Return Rate
- Average Days to Ship

تفکیک‌ها:

- Region
- Category
- Segment
- Month

تحویل:

- Notebook تمیز با توضیح هر مرحله
- داشبورد با Power BI، Tableau، Looker Studio یا Streamlit
- سه Insight قابل اقدام، هرکدام در یک جمله

استفاده از AI برای نوشتن کد مجاز است. دانشجو باید بتواند هر خط را توضیح دهد.
