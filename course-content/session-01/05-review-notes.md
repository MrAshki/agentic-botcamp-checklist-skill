# یادداشت بررسی جلسه ۱

## وضعیت استخراج

- همه ۶۲ صفحه خوانده شدند.
- همه صفحه‌ها لایه متنی دارند.
- اسلایدهای دارای جدول، فرمول، چک‌لیست و پروژه با تصویر اصلی کنترل شدند.
- متن فارسی استخراج‌شده در بعضی خط‌ها ترتیب راست‌به‌چپ نامناسب دارد. نسخه تصویری در این موارد مبنا قرار گرفت.
- این مرحله هیچ تغییری در فایل‌های اسکیل ایجاد نکرد.

## قواعد سرانگشتی که نباید مطلق شوند

- حذف ستون با بیش از ۵۰٪ Missing
- حذف یکی از Featureها با `|r| > 0.85`
- استفاده از median به‌عنوان انتخاب پیش‌فرض برای همه داده‌های عددی
- استفاده از StandardScaler به‌عنوان انتخاب پیش‌فرض بدون بررسی مدل و توزیع
- تقسیم ثابت ۷۰/۱۵/۱۵ برای همه پروژه‌ها
- محدودکردن Pie به دقیقا پنج دسته در همه شرایط

این قواعد نقطه شروع هستند. نوع مسئله، حجم داده، هزینه خطا، ساختار زمانی و هدف کسب‌وکار می‌توانند تصمیم را تغییر دهند.

## نکات نیازمند دقت در استفاده آینده

- Benchmarkهای سرعت و حجم Parquet به Dataset، سخت‌افزار و Query وابسته‌اند.
- قوانین `robots.txt` و شرایط استفاده سایت باید برای هر منبع جدا بررسی شوند.
- مجوز Dataset باید مستقل از امکان دانلود آن بررسی شود.
- Data Dictionary باید از مالک داده یا فرد دارای دانش حوزه تأیید بگیرد.
- Metadata، به‌ویژه EXIF و GPS، می‌تواند اطلاعات شخصی داشته باشد.
- Tool Call و JSON بدون Schema و Validation قابل اعتماد نیستند.
- Test Set نباید برای تنظیم مدل استفاده شود.

## نکات لازم برای ترکیب آینده با چک‌لیست‌ها

- نام جلسه باید همیشه «جلسه ۱ - داده، سوخت هر AI Agent» ثبت شود.
- ارجاع آینده باید نام موضوع را نیز بگوید؛ فقط نوشتن «ج۱» کافی نیست.
- نمونه ارجاع خوب: «جلسه ۱ - داده، سوخت هر AI Agent: Data Leakage و Pipeline».
- برای مسئله مبهم، ابتدا نوع داده، منبع، هدف و کیفیت را مشخص کنید.
- نبود Dataset آماده به‌تنهایی به معنی نقص پروژه نیست؛ امکان جمع‌آوری یا دسترسی باید جدا بررسی شود.
- برای Agent، کیفیت Data Dictionary، Schema، JSON و Dataset ارزیابی بخشی از طراحی اصلی است.
- هیچ بخش این پوشه برای یک دانشجوی مشخص شخصی‌سازی نشده است.
