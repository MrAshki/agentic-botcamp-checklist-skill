# یادداشت بررسی جلسه ۳

## وضعیت استخراج

- تعداد صفحه PDF: ۳۰
- استخراج متن: انجام شد
- رندر تصویری همه صفحه‌ها: انجام شد
- بررسی تصویری همه صفحه‌ها در پنج Contact Sheet: انجام شد
- نمایه صفحه‌به‌صفحه: تکمیل شد
- تغییر در اسکیل: انجام نشد

## کیفیت منبع

- همه صفحه‌ها به‌درستی رندر شدند.
- تیترها، نمودار معماری، جدول‌ها و پرامپت‌های پروژه خوانا هستند.
- استخراج خام متن انگلیسی و کد کیفیت مناسبی دارد.
- ترتیب نویسه‌های فارسی در متن خام برخی صفحه‌ها به‌هم‌ریخته است. محتوای فارسی با تصویر صفحه تطبیق داده شد.
- هشدار FontBBox و Type 3 Glyph مانع رندر یا خواندن محتوا نشد.

## مرز محتوای دوره

- معماری MindEvidence Lab یک نمونه آموزشی برای توضیح API، RAG و محصول است.
- فناوری‌های مشخص مانند Next.js، FastAPI، PostgreSQL، pgvector، DeepSeek و LangGraph انتخاب‌های نمونه هستند. آن‌ها الزام همه پروژه‌ها نیستند.
- عدد ۴۰۰ تا ۷۰۰ Token برای Chunk، تنظیم نمونه پروژه است و باید با داده واقعی ارزیابی شود.
- استفاده از RAG زمانی مناسب است که دانش بیرونی، تازه، خصوصی یا نیازمند استناد وجود دارد.

## موارد زمان‌حساس

پیش از ورود به پیشنهاد عملی اسکیل، این موارد باید با مستندات روز بررسی شوند:

- مدل‌ها و قیمت ارائه‌دهندگان LLM
- محدودیت Context، Tool Calling و سیاست داده
- تنظیمات OAuth گوگل
- نسخه و قابلیت چارچوب‌ها و پایگاه‌های برداری
- منابع پژوهشی و مجوز آن‌ها

## نکات مناسب برای ادغام آینده با چک‌لیست دوره

- تفکیک Model، Agent، Software و Product
- تعیین سطح پروژه: POC، Prototype، MVP یا Product
- انتخاب API یا مدل محلی بر اساس داده، هزینه، تأخیر و عملیات
- استفاده از Workflow ساده پیش از Agent خودمختار
- استفاده از RAG فقط در صورت وجود نیاز دانشی واقعی
- جداسازی Fact، Evidence و Model Interpretation
- ثبت استناد، Audit، خطا، هزینه و Trace
- اعمال مجوز دسترسی پیش از بازیابی داده خصوصی
- نمایش محدودیت و نبود شواهد به‌جای ساخت پاسخ

## موردی که در این مرحله انجام نشد

فایل‌ها هنوز با چک‌لیست‌های نهایی دوره یا اسکیل ترکیب نشده‌اند. این کار پس از استخراج همه جلسه‌ها انجام می‌شود.
