# مسیر ساخت پروژه آموزشی جلسه

## مشخصات پروژه

پروژه نمونه در `docs/SPEC.md` تعریف می‌شود. این فایل هدف، کاربران، مرزها، قابلیت‌ها، معماری، داده، قواعد ایمنی، برنامه ساخت و ساختار مخزن را مشخص می‌کند. فایل Spec زمینه پروژه را به دستیار کدنویسی می‌دهد، اما جای پرامپت کوچک و آزمون هر مرحله را نمی‌گیرد.

## ده مرحله ساخت

### ۱. Frontend با داده Mock

- صفحه ورود، فهرست بیمار، جزئیات بیمار، گفت‌وگو و Evidence Viewer
- داده مصنوعی و بدون Backend واقعی
- نمایش روشن منبع، شواهد و خروجی مدل

### ۲. مدل داده PostgreSQL

- کاربران، Sessionها، بیمارهای مصنوعی، رویدادهای پرونده، سندها و Audit
- Migration، Seed و محدودیت‌های رابطه‌ای
- منع استفاده از اطلاعات شخص واقعی

### ۳. Backend با FastAPI

- Endpointهای بیمار، تاریخچه، Session و سلامت سرویس
- مدل داده و پاسخ ساختاریافته
- جداسازی Route، منطق برنامه و دسترسی داده

### ۴. ورود با Google

- OAuth 2.0 یا OpenID Connect
- Session امن سمت Backend
- دسترسی نقش‌محور و حداقل Scope لازم

### ۵. ورود سند پژوهشی

- استخراج متن و Metadata از PDFهای مجاز
- قطعه‌بندی قابل‌بازتولید
- ثبت صفحه، بخش، عنوان، Hash و نسخه
- بدون ساخت embedding در همین مرحله

### ۶. بازیابی معنایی با pgvector

- ساخت embedding برای Chunkها
- ذخیره بردار و Index
- Endpoint جست‌وجو با `top-k` و فیلتر اختیاری
- آزمون Recall با پرسش‌های مشخص

### ۷. پاسخ مستند با LLM

- حالت General Knowledge، RAG و Both
- پاسخ فقط با استناد به Chunk واقعی در حالت RAG
- اعلام نبود شواهد کافی
- جداسازی Fact، Evidence و Interpretation
- منع تشخیص، تجویز یا تصمیم درمانی

### ۸. هماهنگ‌سازی با LangGraph

- State دارای پرسش، بیمار، شواهد، پاسخ، استناد و Trace
- انتخاب مسیر بازیابی بر اساس حالت پاسخ
- Guardrail پیش و پس از فراخوانی مدل
- محدودیت تعداد مرحله، Timeout و کنترل خطا

### ۹. مشاهده‌پذیری و Audit

- ثبت ورود، پرسش، بازیابی، مدل، استناد، خطا، تأخیر و هزینه
- Correlation ID برای پیگیری یک درخواست در همه اجزا
- داشبورد فعالیت بدون افشای Secret یا داده حساس
- گزارش ایمیلی فقط با رضایت صریح و کمترین مجوز

### ۱۰. یکپارچه‌سازی و نمایش

- اتصال همه مراحل
- آزمون جریان کامل و حالت‌های خطا
- بررسی Secret، دسترسی، استناد و Audit
- ثبت محدودیت‌ها و جداکردن آزمون خودکار از مشاهده دستی
- سناریوی نمایش: ورود، انتخاب بیمار، پرسش مستند و مشاهده منبع

## روش اجرای هر مرحله

- یک هدف کوچک و معیار پذیرش روشن تعریف کنید.
- تغییر را بسازید.
- آزمون مرتبط را اجرا کنید.
- نتیجه واقعی را ثبت کنید.
- Commit کوچک انجام دهید.
- سپس به مرحله بعد بروید.

نباید نتیجه آزمون‌نشده را موفق اعلام کرد.
