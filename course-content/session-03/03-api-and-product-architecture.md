# API و معماری محصول

## API چیست؟

API قرارداد ارتباط بین دو برنامه است. این قرارداد مشخص می‌کند درخواست چه ساختاری دارد، احراز هویت چگونه انجام می‌شود و پاسخ یا خطا چه شکلی است.

اجزای رایج یک درخواست:

- Method مانند `GET`، `POST`، `PUT` و `DELETE`
- URL و مسیر Endpoint
- Header مانند Authorization
- Body یا Query Parameter
- پاسخ با Status Code و داده ساختاریافته

## API در محصول AI

Frontend از API برنامه استفاده می‌کند. Backend می‌تواند از API مدل زبانی، پایگاه داده، سرویس احراز هویت و سامانه‌های سازمانی استفاده کند. کلید سرویس باید فقط در Backend و متغیر محیطی باشد؛ نه در کد Frontend یا مخزن.

برای اتصال به LLM باید این موارد بررسی شوند:

- Provider و مدل
- قالب پیام و پاسخ
- Context Window
- Tool Calling و خروجی ساختاریافته
- تأخیر، سقف درخواست و هزینه Token
- خطا، Timeout، Retry و Fallback
- مجوز، حریم خصوصی و محل پردازش داده

لایه Provider می‌تواند وابستگی مستقیم به یک سرویس را کم کند و تعویض یا Fallback بین مدل‌ها را آسان‌تر سازد.

## مدل آنلاین یا آفلاین

### Online API

- شروع سریع و بدون نگهداری زیرساخت مدل
- دسترسی به مدل‌های قوی و به‌روز
- وابستگی به اینترنت، ارائه‌دهنده، قیمت و سیاست داده

### Offline یا Self-hosted

- کنترل بیشتر بر داده و نسخه مدل
- امکان اجرا بدون ارسال داده به سرویس بیرونی
- نیاز به سخت‌افزار، استقرار، امنیت و نگهداری

انتخاب باید با کیفیت روی داده واقعی، هزینه، تأخیر، حریم خصوصی، پایداری و توان عملیاتی پروژه انجام شود.

## احراز هویت Google

روند کلی OAuth/OpenID Connect در نمونه جلسه:

1. ساخت پروژه در Google Cloud Console
2. تنظیم OAuth Consent Screen
3. ساخت Client ID و Client Secret
4. تعریف Redirect URI مجاز
5. نگهداری Secret در متغیر محیطی
6. ارسال کاربر به Google برای ورود
7. اعتبارسنجی پاسخ و ساخت Session امن در Backend
8. محدودکردن دسترسی بر اساس نقش

Redirect URI، دامنه و پروتکل باید دقیق باشند. Session Cookie باید تنظیمات امنیتی مناسب داشته باشد. برنامه نباید Token یا Secret را در Log یا Frontend افشا کند.

## لایه‌های نمونه معماری

```text
کاربر
  -> Frontend
  -> API Gateway و Auth
  -> Orchestrator یا Workflow
  -> LLM / Retriever / ابزارها
  -> پایگاه داده برنامه، Vector DB و Audit Log
  -> پاسخ، استناد و Evidence Viewer
```

مشاهده‌پذیری، امنیت و حاکمیت باید همه لایه‌ها را پوشش دهند.
